# Brandy Database

Relational database schema and utilities for tracking form submissions, users, events, and trademark analysis results.

## Overview

The Brandy database is designed to:
- Track user accounts and activity
- Store form submissions and answers from the "Brief Brandy" form
- Log events and user interactions
- Store generated brand names and trademark check results
- Cache INDECOPI search results in the database

## Technology Stack

- **Database**: PostgreSQL 12+
- **Driver**: psycopg2
- **Connection Pooling**: SimpleConnectionPool
- **Python**: 3.8+

## Database Schema

### Core Tables

| Table | Purpose |
|-------|---------|
| `users` | User accounts and profiles |
| `events` | Event tracking (form submissions, API calls, etc.) |
| `form_submissions` | Form submission metadata |
| `form_answers` | Individual field answers (normalized) |
| `generated_names` | Brand names generated by the system |
| `trademark_checks` | Trademark check history |
| `similarity_checks` | Name-to-name comparison results |
| `cached_searches` | Database-based search cache |

### Views

| View | Purpose |
|------|---------|
| `v_form_submissions_complete` | Complete form data with all answers |
| `v_user_activity_summary` | User activity statistics |
| `v_popular_names` | Most frequently generated names |

## Usage

### Using Repository Classes (Recommended)

```python
from database.models import (
    UserRepository,
    EventRepository,
    FormSubmissionRepository
)

# Create a user
user_id = UserRepository.create(
    email='user@example.com',
    full_name='John Doe',
    company_name='Acme Inc',
    country='Peru'
)

# Create an event
event_id = EventRepository.create(
    event_type='form_submission',
    user_id=user_id,
    event_name='Brief Brandy Form',
    ip_address='192.168.1.1',
    session_id='abc123'
)

# Create form submission
submission_id = FormSubmissionRepository.create(
    user_id=user_id,
    event_id=event_id,
    form_type='brief_brandy',
    status='completed',
    completion_percentage=100
)

# Add form answers
answers = {
    'resumen': 'Plataforma de e-commerce...',
    'publico': 'Millennials interesados en...',
    'problema': 'Falta de acceso...',
    'competidor1': 'Etsy',
    'personalidad': ['honesta', 'confiable', 'inspiradora']
}

FormSubmissionRepository.add_answers_bulk(submission_id, answers)

# Retrieve submission with answers
submission = FormSubmissionRepository.get_by_id(submission_id)
print(f"User: {submission['full_name']}")
print(f"Answers: {submission['answers']}")
```

### Using Direct SQL

```python
from database import get_cursor, execute_query

# Execute query
with get_cursor() as cursor:

```

### Connection Pooling

```python
from database import get_connection

# Get connection from pool
with get_connection() as conn:
    with conn.cursor() as cursor:
        cursor.execute("SELECT version()")
        version = cursor.fetchone()
        print(version)
# Connection automatically returned to pool
```

## Schema Details

### Users Table

Stores user account information:

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    email VARCHAR(255) UNIQUE,
    full_name VARCHAR(255),
    company_name VARCHAR(255),
    phone VARCHAR(50),
    country VARCHAR(100),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    last_login TIMESTAMP WITH TIME ZONE,
    is_active BOOLEAN DEFAULT TRUE,
    metadata JSONB DEFAULT '{}'::jsonb
);
```

### Form Submissions Flow

1. User fills out form → tracked in `events`
2. Form submitted → metadata in `form_submissions`
3. Each field → stored in `form_answers`
4. Names generated → stored in `generated_names`
5. Trademark checks → stored in `trademark_checks`

### Form Answers Structure

The `form_answers` table uses a normalized EAV (Entity-Attribute-Value) pattern:

| Column | Description |
|--------|-------------|
| `submission_id` | Links to form_submissions |
| `field_name` | Name of form field (e.g., 'resumen', 'publico') |
| `field_value` | Value entered by user |
| `field_type` | Type of field (text, textarea, checkbox, url) |
| `field_order` | Display order of fields |

### Retrieving Complete Form Data

Use the `v_form_submissions_complete` view:


## Cache Management

### Database-Based Cache

The `cached_searches` table replaces the file-based pickle cache:

```python
from database.models import CacheRepository

# Get cached result
result = CacheRepository.get(
    query='TechNova',
    search_type='phonetic',
    category=9
)

if result:
    print(f"Cache hit! Found {len(result['results'])} results")
else:
    # Perform search
    results = perform_indecopi_search(...)

    # Cache results
    CacheRepository.set(
        query='TechNova',
        search_type='phonetic',
        results=results,
        category=9,
        expiry_days=7
    )
```

### Clear Cache

```python
# Clear expired entries
deleted = CacheRepository.clear_expired()
print(f"Cleared {deleted} expired entries")

# Clear all cache
deleted = CacheRepository.clear_all()
print(f"Cleared {deleted} total entries")
```

Or use SQL:
```sql
-- Clear expired
SELECT clean_expired_cache();

-- Clear all
DELETE FROM cached_searches;
```

```sql

SELECT event_type, COUNT(*) as count
FROM events
GROUP BY event_type
ORDER BY count DESC;

-- Daily form submissions
SELECT DATE(submitted_at) as date, COUNT(*) as submissions
FROM form_submissions
GROUP BY DATE(submitted_at)
ORDER BY date DESC;

-- Average form completion time
SELECT AVG(time_spent_seconds) / 60.0 as avg_minutes
FROM form_submissions
WHERE status = 'completed';
```

## Troubleshooting

### Connection Issues

**Error**: `psycopg2.OperationalError: could not connect to server`

**Solutions**:
1. Check PostgreSQL is running:
   ```bash
   sudo systemctl status postgresql
   # or
   brew services list
   ```

2. Check connection settings in `.env`:
   ```env
   DB_HOST=localhost
   DB_PORT=5432
   ```

3. Test connection:
   ```bash
   psql -U postgres -h localhost
   ```

### Permission Issues

**Error**: `psycopg2.errors.InsufficientPrivilege`

**Solution**: Grant permissions
```sql
GRANT ALL PRIVILEGES ON DATABASE brandy TO your_user;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO your_user;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO your_user;
```

### UUID Extension Missing

**Error**: `function uuid_generate_v4() does not exist`

**Solution**:
```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

## Integration with Brandy

### Form Handler Example

```python
from flask import Flask, request
from database.models import (
    UserRepository,
    EventRepository,
    FormSubmissionRepository
)

app = Flask(__name__)

@app.route('/api/submit-form', methods=['POST'])
def submit_form():
    data = request.json

    # Get or create user
    user = UserRepository.get_by_email(data['email'])
    if not user:
        user_id = UserRepository.create(
            email=data['email'],
            full_name=data.get('full_name'),
            country='Peru'
        )
    else:
        user_id = user['id']

    # Create event
    event_id = EventRepository.create(
        event_type='form_submission',
        user_id=user_id,
        ip_address=request.remote_addr,
        user_agent=request.headers.get('User-Agent')
    )

    # Create submission
    submission_id = FormSubmissionRepository.create(
        user_id=user_id,
        event_id=event_id,
        completion_percentage=100
    )

    # Store answers
    FormSubmissionRepository.add_answers_bulk(submission_id, data['answers'])

    return {'success': True, 'submission_id': submission_id}
```
